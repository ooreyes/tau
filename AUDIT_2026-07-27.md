# Tau audit - 2026-07-27

Three independent read-only audits (LTspice parity, performance, security) run against
`auto/ltspice-parity` @ 7691351. Every claim below carries file:line evidence and was
verified against code, not docs.

**Headline: `PROGRESS.md`'s `READINESS: NOTARIZATION-ONLY` is not accurate.** Two
independent reasons: the release config cannot pass notarization as written (S2), and
several classes of circuit silently produce confidently wrong answers (P1-P8).

---

## Class A - silently wrong answers (trust-destroying)

These do not fail. They return a plausible number that is wrong, with no warning. For an
engineering tool this is worse than refusing to run.

| id | defect | evidence |
|----|--------|----------|
| P1 | Unknown semiconductor models are swapped for generic `Level=1` starters with no diagnostic. 28 bundled models vs LTspice's 2,569 = **1.1% coverage**. An `IRF540` simulates as a textbook NMOS. | `engine/spiceNetlist.ts:447-450`, `engine/standardModels.ts:19-61` |
| P2 | Voltage-controlled switches emit `R_<name> a b 1e12` - a permanent open circuit. Both control pins are dropped at import. Kills every SMPS/relay/ideal-switch circuit. | `io/ascImport.ts:482`, `engine/spiceNetlist.ts:780-783` |
| P4 | `.step` silently truncates to 16 points. `.step param RL 1k 100k 1k` runs to 16k, not 100k. | `simulation/stepFamily.ts:41,86` |
| P7 | `.asc` export writes `switch`/`comparator`/`cccs`/`ccvs`/`subckt`/`testpoint` as `SYMBOL res` `Value 1T`. Round-trips in Tau via `Tau*` attrs; opens in LTspice as open circuits. `warnings: []`. | `io/ascExport.ts:226-240,333` |
| P8 | Transformer hardcodes `primaryInductance = 10e-3` and `k = 0.999`. Magnetizing and leakage inductance - the two design parameters of a flyback - are unreachable. | `engine/spiceNetlist.ts:784-794` |
| P11 | `.noise` models resistor thermal noise only. Op-amps are in `NOISE_SUPPORTED` but contribute zero noise, so an op-amp front end returns a clean, wrong curve. | `simulation/noise.ts:380-381,487,520-521` |
| P14 | TRIAC imports as an NPN; DIAC and varistor as 1 MΩ resistors. Informational note only - the deck builds and runs. | `io/ascImport.ts:378-386` |
| P15 | Unmappable symbols are dropped and the circuit still simulates. Nothing gates Run. | `io/ascImport.ts:1449-1453` |

## Class C - security

| id | severity | defect |
|----|----------|--------|
| S1 | **Medium** | `deck_lines` screens one *physical* line; ngspice screens the *stitched* logical card. Splitting `input_file` and `= "path"` across a `+` continuation passes both the dot-card allowlist and the file-primitive screen, then reassembles inside ngspice. Reachable from a downloaded `.lib` (every vendor macromodel is a `.subckt`, captured verbatim) or a downloaded `.asc`. Yields an arbitrary-path existence oracle and plausible local file read into plotted trace data. Not RCE - `.control` remains unreachable. Fix: unfold continuations *before* screening, keep emitting the original physical lines. `src-tauri/src/spice.rs:902-914`, `engine/userModelLibrary.ts:235-251`, `engine/modelDirectives.ts:140-155` |
| S2 | **Low sev / release blocker** | `"signingIdentity": "-"`, `"hardenedRuntime": false`. Ad-hoc signing with library validation off, while Tau `dlopen`s `libngspice.dylib` and re-execs itself as a worker. **This configuration cannot pass Apple notarization**, which contradicts the `NOTARIZATION-ONLY` readiness claim. `src-tauri/tauri.conf.json:36-40` |
| S3 | note | `.claude/settings.json` + `.cursor/hooks.json` register Stop hooks that execute `scripts/checkpoint.sh` and `scripts/refresh-tau-app.sh`. Harmless when shipped, but cloning a public repo would auto-execute them in an agent session. Strip before publication. |

**Verified intact** (attempted bypasses failed): dot-card allowlist vs Unicode whitespace /
case / `+.include` / lone `\r`; `.end` positioning; double `deck_lines` enforcement across
IPC; release builds ignoring `TAU_NGSPICE_LIB`; `project_fs` canonicalization, symlink
source+target guards, `create_new(true)` exclusive create, `safe_leaf_name`; hierarchical
symbol path traversal; CSP (`script-src 'self'`, no `unsafe-eval`, 12 commands, no shell or
http plugin); the `<tau_context>` envelope on **both** providers; `inspect_simulation_signal`
read-only with no `eval` anywhere; mutation tools proposal-only behind an explicit click;
zero `dangerouslySetInnerHTML`/`innerHTML`; API key in the **OS keychain** (not localStorage,
the old note is stale), never logged, only two outbound hosts matching CSP; repo secret scan
clean. `cargo audit` zero vulns; `pnpm audit` 1 high + 1 low, both dev-only transitive
`vite` deps, absent from the shipped bundle.

## Class D - performance

Measured with in-tree micro-benchmarks. `crates/` holds only a README - no Rust to audit.

| id | win | defect |
|----|-----|--------|
| F1 | **19-32x** on the solve | Transient re-factorizes a provably time-invariant matrix every timestep, using Gauss-Jordan (~1.5x LU's work) plus an augmented deep copy. Fix: LU-factor once, forward/back substitute per step. 5000 steps, n=60: 713ms -> 22ms. `simulation/linearTransient.ts:440,625,1103-1129` |
| F2 | freeze -> responsive | DC sweep re-extracts the entire netlist per sweep point (clone every component + full `extractCircuit` + O(n^2) stamping + fresh O(n^3) solve), synchronously on the main thread, no progress, no Stop. `MAX_POINTS = 100_001`. `simulation/dcSweep.ts:185-196`, `App.tsx:696-698` |
| F3 | high | Full `extractCircuit` on **every pointer move**, purely to decide a boolean. `components/Canvas.tsx:756` (+`:528,547,562`); `netAtPoint` is O(labels x nets x points). |
| F4 | 70ms -> ~1ms/frame | Label placement rebuilds `[...componentRects, ...wireRects, ...placed]` per candidate per component. At 800 comps/1500 segs this alone caps drag at 14fps. `components/Canvas.geometry.ts:478-482` |
| F5 | high | `tracePath` is called inline in render (not memoized) and `waveformEnvelopeIndices` linear-scans **all** samples regardless of window size. `times` is monotonic - binary search. Panning re-renders every pane: 12 x 200k scans per pointermove. `simulation/waveform.ts:201-212`, `components/SimulationPanel.tsx:1556,1669` |
| F6 | med-high | `.asc` import is O(components x pins x wires) - ~8-16 full wire scans per component. Fix: bucket wires by fixed axis, the pattern `netlist.ts:166-180` already uses. `io/ascImport.ts:926-937` |
| F7 | **4.8x** | Complex arithmetic allocates an object per operation; `zeroCMatrix` allocates n^2 objects per frequency point. n=40 x 301 points: 86ms -> 18ms with interleaved `Float64Array`. `simulation/acSweep.ts:53-63,89-95,134-172`; `simulation/noise.ts` does two O(n^3) complex solves per point. |
| F9 | **up to 176x** | `rootToPoints.set(root, [...(get() ?? []), pt])` copies the whole array per append - O(k^2) per net, and **ground is always the largest net**. 5000-pt net: 15.1ms -> 0.09ms. `schematic/netlist.ts:216,222` (+`:99,172,174,178,361`) |

## Status - 2026-07-28

Gates on the current tree: **tsc clean · 2153 JS tests · 31 Rust · clippy 0 · corpus
80/80 imported, deck-built, op-converged and schema-valid.**

**Corpus caveat:** the recorded baseline is 82 files and only 80 are on this machine -
`~/Downloads/LTspice_export` no longer exists (removed in an earlier disk cleanup), so
`scripts/acceptance-corpus.sh` fails its `>= 82` assertion. The baseline was deliberately
NOT lowered: it is correctly reporting missing inputs, not a code regression. Restore that
directory to make the gate meaningful again. Note that passing `CORPUS_EXTRA_ROOTS=` (even
to a path that does not exist) silently disables the baseline assertion.

### Closed

- **P3 (`.dc` half)** `runNativeDcSweep` (`engine/nativeSpice.ts`) runs `.dc` on ngspice
  and `App.tsx`'s `runDcAnalysis` prefers it, so a MOSFET or BJT transfer curve is
  sweepable for the first time - the TS solver re-solves an operating point per step and
  has no semiconductor stamps. The axis comes off ngspice's source-typed scale vector
  (`v-sweep`/`i-sweep`, both confirmed against the host's real ngspice), and a nested run,
  which ngspice returns as one flat inner-major vector, is split back into one curve per
  outer value. The spec is validated before the native round trip so an unknown or
  non-source sweep target and a runaway curve count keep their actionable messages.
- **P1** model substitution now names the part and the consequence, with tests.
- **P2** voltage-controlled switches switch. `sw` imports its NC+/NC- pair
  (`io/ascImport.ts` `LTSPICE_PINS.sw`), the `switch` kind carries `cp`/`cn`
  (`schematic/pins.ts`), and the deck emits `S <a> <b> <cp> <cn> <model>` against the
  document's own `.model` or a `TAU_SW` starter (`engine/spiceNetlist.ts`). Proved on the
  host's real ngspice: the same deck reads 5 mV at the load with the control at 0 V and
  4.995 V at 2 V. A switch that names a model but has no wired control pair - `csw`, whose
  control is a named source, or a `.cir`-imported `S` - stays a fixed resistance and now
  says so (`uncontrolledSwitchWarning`) instead of quietly opening the circuit.
  **Three near-misses worth recording**, each caught by a test rather than by review:
  (1) the deck referenced `TAU_SW` while `DEFAULT_MODELS` was gated to semiconductor kinds,
  so ngspice would have died on an undefined model; (2) the two new optional pins made
  `extractCircuit` emit "only connected to one pin" for every *static* switch, and
  `assistantActions` treats any extraction warning as fatal - it would have refused every
  schematic containing a switch; (3) the same dangling pins became all-zero rows in the
  four TS preview solvers, whose gmin shunt was gated to op-amps/diodes, so AC/OP/transient
  previews returned "matrix is singular" on any switch circuit.
- **P4** `.step` truncation now warns (`stepTruncationWarning`), and - critically - the
  notice is now *rendered*: `StepPlot` previously showed the plot, legend and meters but
  never `result.warnings`, so the warning would have been computed and stored and never
  seen. Falsified both ways.
- **P7** lossy `.asc` export now names every part saved as a placeholder resistor.
  **Near-miss worth recording:** `ascSaveBlockReason` treated *any* export warning as a
  save blocker, so the new notice would have made Tau refuse to save any schematic
  containing a switch, subcircuit, comparator, CCCS, CCVS or test point - far worse than
  the silent loss it was fixing. Carrier notices are now filtered via
  `isLossyCarrierWarning`, with a regression test.
- **P8** transformer magnetizing and leakage inductance are reachable
  (`transformerWindings`: `L1=`, `L2=`, `k=`, falling back to the turns ratio) instead of
  hardcoded 10 mH / k=0.999.
- **P13** FET current probing (one-line kind-name fix) with a test tying the probe list to
  `ComponentKind`.
- **S1** deck continuation-fold bypass closed and tested.
- Import UX: unified surface, drag-and-drop, content-based format routing, KiCad netlist
  import. **Real bug found and fixed while gating:** `ensureProjectDestination` routed the
  no-filesystem case to `openFolder()`, which can only return null there, so a dropped file
  dead-ended on "Choose a Schematics folder" with no way to choose one.
- Light theme shipped with a System/Light/Dark control, plus `--status-ink-mix`: the Run
  button's label was `color-mix(..., white)`, which is invisible on a pale fill. A
  hex/rgba scan does not catch a bare color *keyword* - see DESIGN_SYSTEM.md section 7.
- `scripts/design-shot.mjs` now captures **both themes**; it had silently stopped covering
  dark the moment light tokens landed, because Playwright defaults to light.
