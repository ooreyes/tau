Tau (`/Users/omarreyes/Desktop/Tau`) is a Tauri/React circuit simulator ("LTspice replacement"), pnpm workspace, app at `apps/desktop`. Canonical branch `auto/ltspice-parity`. The repo runs an **autonomous build loop** (see `AGENTS.md`, `PROGRESS.md` heartbeat, `CLAUDE.md`) — a bot claims units of work, commits, and pushes continuously. `PROGRESS.md`'s heartbeat block shows what's currently claimed; check it before assuming the repo is idle.

**Why:** interactive sessions and the autobuilder share this repo, so uncommitted work can coexist with an actively-running bot. Don't assume a clean tree.
**How to apply:** before large edits, `git status`/`git diff` first — there may already be uncommitted, intentional work (see [[feedback_preserve_uncommitted_fixes]]). Never commit unless the user explicitly asks (bot does its own commits via the loop in AGENTS.md, but that's a different actor than an interactive session).

## Stack / structure
- React + TypeScript, Tauri desktop shell. `pnpm -C apps/desktop typecheck` / `test` / `build` / `dev` are the check commands. `pnpm dev:web` runs a browser-only dev server (used by `scripts/design-shot.mjs`) since Tauri-native ngspice isn't available in-browser — a TS fallback transient solver runs instead (`engine/nativeSpice.ts` `isNativeSpiceRuntime`).
- Design tokens: **sole `:root`** at the top of `apps/desktop/src/App.css` (~140 lines) — surfaces, borders, text, `--accent-*`, `--signal-*` (amber/tactical), `--danger-*`/`--success-*` (semantic), `--trace-*` (6-color waveform palette), spacing `--sp-*`, type `--fs-*`, motion `--motion-*`/`--ease-*`. `apps/desktop/src/styles/tokens.css` maps these onto Tailwind v4's `--color-*` namespace via `@theme inline` and **wipes Tailwind's stock palette** (`--color-*: initial`) — `bg-red-500` etc. is a build error. Every color must route through an App.css token. Tailwind *layout* utilities (flex/gap/etc, non-color) are used freely even in older files like SimulationPanel.tsx.
- Simulator UI: `apps/desktop/src/components/SimulationPanel.tsx` (~3000 lines) — one big component with 7 analysis tabs (TRAN/OP/AC/DC/TF/NOISE/STEP). Companion files: `ComponentMeasurementsPanel.tsx` (per-component V/I/P; has a `variant="full"|"compact"` prop — compact is a horizontal-scroll card strip, reused by `TelemetryDock.tsx`), `TelemetryDock.tsx` (collapsible per-component telemetry dock under the simulator's read-only schematic, in App.tsx — NOT inside SimulationPanel), `cardLayout.ts` (pure reducer for the TRAN tab's snap-tiling 2-col dashboard grid: plot panes + Measurements/Fourier tables as drag-reorderable/resizable cards, keyed by trace id not pane id/index — mirrors `plotPanes.ts`'s pure-module style), `AnalysisSetupForms.tsx` (DcSetupForm/TfSetupForm/NoiseSetupForm/StepSetupForm), `Toolbar.tsx` (top toolbar incl. Run button + status lamp), `usePlotViewport.ts` (zoom/pan hook, shared-X viewport for multi-pane scope), `PlotAxes.tsx`, `ScopeZoomCluster.tsx`, `EngineeringTraceReadout.tsx`, `panelResize.tsx` (drag-resize machinery — `usePanelWidth`/`PanelResizeHandle`; `edge` supports all 4 sides, "top"/"bottom" repurpose the width math for a *height* drag, e.g. the telemetry dock).
- The schematic canvas is **not** a `<canvas>` element — it's an SVG (`svg.canvas`) with custom pointer-based hit-testing (wires have an invisible wider `.wire-hit` path, pins are `.pin-target` circles). No DOM element per net; Playwright/browser-automation clicks need real hit-target bounding rects, not visual guesswork.
- Visual verification script: `scripts/design-shot.mjs` — captures fixed app states (empty/schematic/inspector/simulator/dialog/command) at 3 viewports to `screenshots/<label>/`. It hardcodes `http://localhost:1420`; if a server is already listening there it **reuses it and never kills it** (only kills a server it spawned itself) — safe to run against a live user dev server without disrupting it.
